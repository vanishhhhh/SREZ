# Черновик ТЗ: каталог проектов «Срез»

## Цель

Создать HTTP-сервис, через который участники видят проекты, а руководитель управляет их списком. На этапе занятия №3 реализован только просмотр списка с заранее заданными данными.

## Роли

- Участник — просматривает список и сведения о проектах.
- Руководитель — создаёт, изменяет и удаляет проекты.

Роли описывают будущие сценарии. Авторизация и проверка прав на текущем этапе не реализованы.

## Сущности

Проект (`Project`): `id` — целочисленный идентификатор, `title` — название.

## Сценарии

1. Участник открывает список проектов и видит их идентификаторы и названия.
2. Участник выбирает проект и просматривает его сведения.
3. Руководитель создаёт проект с названием.
4. Руководитель изменяет название существующего проекта.
5. Руководитель удаляет завершённый проект.

## HTTP-маршруты

| Метод | Путь | Назначение | Ответ при успехе | Этап |
| --- | --- | --- | --- | --- |
| GET | `/projects` | Список проектов | `200`, JSON-массив | Реализован: фиксированный список |
| GET | `/projects/:id` | Сведения о проекте | `200`, JSON-объект | Запланирован |
| POST | `/projects` | Создание проекта, тело `{"title":"Название"}` | `201`, JSON-объект | Запланирован |
| PUT | `/projects/:id` | Изменение проекта, тело `{"title":"Название"}` | `200`, JSON-объект | Запланирован |
| DELETE | `/projects/:id` | Удаление проекта | `204`, без тела | Запланирован |

## Критерии готовности текущего этапа

- Приложение запускается через `go run ./cmd/app`.
- `HTTP_ADDR` задаёт адрес сервера; значение по умолчанию — `:8080`.
- `GET /projects` возвращает статус `200`, JSON и два проекта: «Дело» и «Витрина» с идентификаторами `1` и `2`.
- HTTP-логика находится в `internal/handler`; `main` читает конфигурацию и запускает обработчик.
- Пакеты `internal/usecase` и `internal/storage` существуют и содержат только объявления пакетов.
- Dockerfile собирает приложение; контейнер возвращает тот же список, что и локальный сервер.
