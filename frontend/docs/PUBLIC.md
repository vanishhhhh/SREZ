# Публичная витрина SREZ — результат локального этапа

> Исторический отчёт публичного этапа. Актуальная integration-repository использует localhost:5174/API8081 и реальный managed Media backend. Итоги: [INTEGRATION_REPORT.md](INTEGRATION_REPORT.md).

Дата: 16.11.2026. Рабочая копия: `C:\dev\team-repository`.

## Результат

Сохранён существующий визуальный стиль: Manrope, нейтральный фон, крупная типографика, чёрные акценты, редакционный hero. Публичные страницы используют настоящий Go API. В runtime нет фиксированных массивов товаров, брендов, цен или остатков. SVG в hero — декоративная иллюстрация.

| Страница               | Данные                                                                                                  | Что реализовано                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `/`                    | GET `/products?sort=newest&limit=4`, GET `/products?category=hoodie&sort=newest&limit=4`, GET `/brands` | Hero, две независимые подборки, все 7 категорий, бренды с логотипами, переходы и footer  |
| `/catalog`             | GET `/products`, GET `/brands`                                                                          | Фото/название/бренд/цена/размеры/цвета/наличие; все фильтры, 5 сортировок, пагинация     |
| `/products/:productId` | GET `/products/:id`; отдельный необязательный GET `/brands`                                             | Галерея, цвет, доступные размеры и остатки, описание/материалы, информация о бренде      |
| `/brands`              | GET `/brands`                                                                                           | Directory активных брендов, логотипы, описание, состояния загрузки/ошибки/пустого списка |
| `/brands/:slug`        | GET `/brands/:slug`, GET `/products?brand_id=:id&limit=12&sort=newest&page=:page`                       | Баннер, логотип, история, публичные контакты и полный каталог бренда с пагинацией        |

Все эти GET публичны. Браузер обращается через `/api`; Vite удаляет этот префикс. Существующий `/media` proxy сохраняет путь. Публичный каталог не запускает refresh JWT при ошибке своего GET.

## Поведение каталога

- Применённые параметры находятся в URL. Черновик полей применяется кнопкой «Показать вещи»; сортировка применяется сразу. Изменение фильтра/сортировки сбрасывает page на 1. Back/forward восстанавливает поля.
- Категория и бренд — select; размер и цвет — текстовые поля по текущему API. Справочника фасетов backend не предоставляет. Цвет не подменяется произвольным CSS-цветом.
- Цена вводится в рублях; API получает целые копейки. Например, `2000,01` → `min_price=200001`. Не допускается min > max.
- API возвращает **массив** карточек. Число вещей и страниц берётся строго из `X-Total-Count`, `X-Page`, `X-Limit`, `X-Total-Pages`. Отсутствующие/повреждённые метаданные дают понятную ошибку с повтором.
- Сохранён валидный `limit` из URL при применении фильтров. Неверные параметры возвращают ошибку API и действие «Сбросить параметры запроса».
- Пустая дальняя страница сохраняет навигацию «Назад», ведущую на последнюю существующую страницу. Пустая выборка предлагает сбросить фильтры.
- Каталог не делает дополнительных запросов бренда для каждой карточки: `brand_name`, `brand_slug`, обложка и признаки наличия уже приходят в ProductCard.

## Товар, изображения и устойчивость

Выбор размера хранит variant ID и всегда проверяется внутри выбранного цвета с `stock > 0`. Смена цвета сбрасывает размер и фото. У недоступного размера кнопка disabled; полностью закончившийся цвет можно посмотреть, но выбрать его вариант нельзя. Счётчик stock показывается для выбранного доступного варианта. Это снимок ответа API, не резервирование товара.

Галерея поддерживает миниатюры и предыдущий/следующий ракурс. На сфокусированной области галереи работают ArrowLeft/ArrowRight. Сбой фотографий не ломает страницу; смена URL/ракурса сбрасывает ошибку изображения.

`Media` принимает legacy HTTPS URL без credentials и относительные `/media/assets/:id/content` через Go. Неподдерживаемые пути, HTTP, `javascript:`, protocol-relative ссылки и S3 query credentials отклоняются. Есть skeleton до загрузки и placeholder при отсутствующем/недоступном фото. Ни SDK хранилища, ни приватных ключей во frontend нет.

Независимые разделы главной загружаются отдельно. Ошибка справочника брендов не скрывает товар; есть действие повторного чтения бренда. Ошибка брендов в каталоге не отключает остальные фильтры. Для 404 товара/бренда предусмотрены отдельные состояния и рабочий путь назад. На пустой БД отображается отсутствие опубликованных данных.

## Ограничения и следующие зависимости

1. В этой локальной копии отсутствуют Go-маршруты Media Storage и сервис SeaweedFS. Поддержка формата `/media/assets/:id/content` и pass-through proxy готовы, но live-чтение такого asset подтвердить пока нельзя. Полный сценарий проверен контролируемым ответом, не выдаётся за проверку хранилища.
2. Public product detail не содержит компактного бренда. Сейчас отдельный `/brands` используется один раз на страницу товара; его ошибка изолирована. Для большого справочника можно добавить backend DTO/кэш отдельной задачей.
3. Backend не отдаёт фасеты размеров/цветов. Поля принимают реальные названия из каталога; источник вариантов не выдумывается.
4. Нет покупательских favorites/cart/order контрактов в этой копии. Публичный этап не создаёт кнопок покупки с фиктивным действием. Работы по корзине и seller-панели не начинались.
5. Сегодня проверен Chrome. Дополнительные браузеры и отдельная ручная проверка browser zoom 200% остаются в плане. Существующий Node/npm стек и зависимости сохранены, новых библиотек не добавлено.

## Локальный запуск в Windows PowerShell

Основной адрес: **http://127.0.0.1:5173**. API: **http://127.0.0.1:8080**. Если они уже работают, достаточно открыть сайт. Команды для повторного запуска:

```powershell
Set-Location 'C:\dev\team-repository'
node .\frontend\scripts\prepare-local.mjs
docker compose -f compose.yaml -f compose.frontend.yaml up -d --build
```

Во втором окне:

```powershell
Set-Location 'C:\dev\team-repository\frontend'
npm install
npm run dev
```

При остановке процесса `npm run dev` сайт становится недоступен. Для независимого фонового запуска из `frontend` добавлен `scripts/start-dev.ps1`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-dev.ps1
```

Он запускает Vite отдельным скрытым процессом с обычным API 8080, проверяет HTTP 200, сообщает PID и путь к логам. Занятый 5173 не освобождается принудительно. Скрипт не запускает и не меняет БД; после перезагрузки Windows запускается повторно.

Override сохраняет `SREZ_PUBLIC_ORIGIN=http://127.0.0.1:5173`, `SREZ_AUTH_LOCAL_HTTP=true`; backend-проверки Origin/CSRF/JWT включены. Не смешивайте localhost и 127.0.0.1 для auth. `prepare-local.mjs` сохраняет существующие значения `.env`. Не удаляйте volumes для перезапуска.

Обычные проверки:

```powershell
npm test
npm run build
npm run format:check
```

### Повторить live E2E, сохранив рабочую БД

Окно 1, в корне репозитория, со свободным 8081:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\frontend\scripts\auth-test-api.ps1 -ApiPort 8081 -PublicOrigin http://127.0.0.1:5174
```

Скрипт создаёт отдельные именованные контейнеры/volume/сеть и ждёт Enter. Нажатие Enter останавливает **только созданные им два контейнера**, сохраняя все данные. Существующий сервер при занятом порте не останавливается. Каждый запуск создаёт новый тестовый volume; это намеренно безопаснее автоматического удаления.

Окно 2, из `frontend`, со свободным 5174:

```powershell
$env:SREZ_API_TARGET='http://127.0.0.1:8081'
npm run dev -- --port 5174
```

Окно 3, из `frontend`:

```powershell
$env:SREZ_PUBLIC_E2E_URL='http://127.0.0.1:5174'
$env:SREZ_PUBLIC_E2E_LIVE='1'
npm run test:e2e:public
$env:SREZ_E2E_BASE_URL='http://127.0.0.1:5174'
$env:SREZ_AUTH_E2E_LIVE='1'
npm run test:e2e:auth
```

Live-флаги включайте только для отдельного тестового API: сценарии создают сохранённые записи. Без live-флага публичный набор выполняет 2 контролируемых сценария и пропускает 7 live; auth выполняет 8 и пропускает 1 live. Playwright использует установленный Google Chrome, не публикует отчёты и не пишет токены в trace/video. Отчёт последнего запуска находится в `frontend/playwright-report`, скриншоты — в игнорируемом `frontend/test-results`.
