# Brand Page Builder · Phase 1

## Architecture

Конструктор хранит композицию витрины и палитру в `BrandPageConfig`. В версии 1 есть `schema_version`, упорядоченный массив `blocks` и три цвета в `appearance`. У блока есть стабильный `id`, тип, композиция `layout` и типизированное содержимое `content`. Положение определяется индексом в массиве. Перестановка сохраняет ID, поэтому React и будущие ссылки на медиа могут опираться на него.

| Тип | Композиции | Источник | Наличие |
| --- | --- | --- | --- |
| `hero` | `full-width`, `split` | `brand_banner` и название бренда | Обязательный |
| `story` | `text`, `split` | `brand_story` (название, логотип, описание) | Обязательный |
| `products` | `grid` | `brand_catalog` (текущий `brand_id`) | Обязательный |
| `contacts` | `inline` | `brand_contacts` (сайт, Telegram, email) | Опциональный |

Каждый тип встречается один раз. Новая композиция добавляется в допустимые варианты типа на сервере и в renderer. Для нового типа понадобятся проверка собственного содержимого, UI настройки и ветка рендера. Несовместимые изменения схемы требуют новой версии с чтением старых конфигураций или явным преобразованием.

В PostgreSQL одна запись на бренд хранит `draft` и `published` в JSONB. Это позволяет сохранять и публиковать небольшую композицию целиком. Ревизия начинается с 0, увеличивается при сохранении и публикации. Публичная витрина получает снимок композиции и палитры. Название, описание, контакты, логотип, баннер и товары остаются живыми данными. Для бренда без снимка используется стандартная композиция с нейтральной палитрой. Legacy `BrandAppearance` служит стартовым значением только для редактора до первого сохранения.

## Backend

Миграция `016_brand_page_builder.sql` добавляет таблицу `brand_pages` с внешним ключом, лимитами JSON и ограничениями ревизий. Существующие бренды получают стартовую композицию при чтении без записи в БД.

Management usecase проверяет активное членство владельца и статус бренда в существующей транзакции под блокировкой строки бренда. После проверки ревизии repository сохраняет черновик или атомарно копирует валидный черновик в опубликованный снимок. Снимок доступен посетителям при активном статусе бренда. Действующие правила публикации бренда и фильтрация каталога по статусам продолжают действовать.

HTTP API проверяет размер тела до 8 КиБ, неизвестные поля, версию схемы, 3–4 блока, обязательные типы, уникальные ID длиной до 40 ASCII-символов, пары типа, композиции и источника, а также три строковых HEX-поля палитры. В версии 1 произвольный текст, адреса объектов и разметка отсутствуют в конфигурации. Приватные операции возвращают 403 для editor и 404 при чужом бренде или отозванном членстве. При устаревшей ревизии API возвращает 409. Публичный endpoint возвращает только опубликованную конфигурацию. [Маршруты и коды ответов](api-reference.md#оформление-страницы-бренда).

## Frontend

Владелец открывает «Оформление страницы» в Studio. На широком экране блоки и настройки видны рядом с предпросмотром. На телефоне между ними можно переключаться. Блоки переставляются кнопками, контакты добавляются и удаляются отдельно. Есть переключатель ширины предпросмотра, сохранение черновика и отдельная публикация. Защита от несохранённых изменений использует существующий диалог. При конфликте текущие поля сохраняются в форме до подтверждения загрузки актуального черновика.

Публичная витрина и предпросмотр используют `BrandPageRenderer`. Товары загружаются через публичный каталог и сохраняют существующие карточки и пагинацию. При отсутствии баннера обложка показывает название, а пустой блок контактов скрывается. Переменные палитры действуют внутри витрины. HEX с альфа-каналом смешивается с базовым цветом, для текста и акцента подбирается доступный цвет при контрасте ниже 4.5:1.

## Personal Pages Polish

- «Мои вишлисты» без точки и надписи «СОБИРАЙ СВОЙ ВЗГЛЯД». На форме создания оставлен заголовок «Новый вишлист». Фраза «Твой стиль начинается с одной вещи» уже отсутствовала в базовой версии. На экранах просмотра убраны «ПОДЕЛИТЬСЯ ВЗГЛЯДОМ», «СОБРАНО ТОБОЙ», «SREZ / ЛИЧНЫЙ ВЗГЛЯД», «У каждого свой SREZ» и два подставных описания. Подсказки про приватность, публичную ссылку и её отзыв сохранены.
- У «Избранного» убрана надпись «ЛИЧНЫЙ ВЫБОР». Подпись «Вещи, к которым хочется вернуться» сохранена.
- У «Моих заказов» убрана надпись «ИСТОРИЯ ВАШЕГО ВЫБОРА». Новое описание «Здесь можно посмотреть заказы и их статусы. Оплата пока не подключена.»
- Пустая история сохранила заголовок «История ещё впереди» и переход в каталог. Подпись теперь сообщает, что заказы появятся после оформления корзины.
- Механика вишлистов, сердечек, заказов, резервирования и оплаты осталась прежней.

Frontend unit tests покрывают разбор конфигурации, HEX и контраст. Playwright проверяет редактирование, перестановку, контакты, защиту формы, публикацию, конфликт ревизии, публичную витрину и заголовки личных страниц. Проверены ширины 1440, 834, 390 и 360 px.

## Next Phase · Brand Media & Editorial Layouts

1. **Независимые изображения.** Расширить существующий Media Storage назначением для редакционных изображений бренда. Загрузка проходит через действующий staging и finalize. Ссылки в блоках содержат ID готовых объектов. Под блокировкой бренда при записи и публикации сервер проверяет назначение, готовность, владельца и принадлежность каждого объекта бренду. Покрыть тестами чужие ссылки, отзыв доступа и повторный finalize.
2. **Жизненный цикл.** Ввести таблицу ссылок на изображения для обоих снимков. Обновлять ссылки в той же транзакции, что и конфигурацию. Удаление блока освобождает ссылки нужного снимка. Физическое удаление производится существующим механизмом после истечения периода восстановления и повторной проверки обоих состояний. Протестировать гонку удаления и публикации, rollback и недоступные объекты.
3. **Форматы и кадрирование.** Добавить ограниченные пресеты высоты для баннера и соотношения сторон для фотографий. Хранить координаты фокуса в долях кадра, валидировать диапазон 0–1 и применять их одинаково в предпросмотре и публичной витрине. Поддержать отдельный мобильный фокус и последовательность колонок.
4. **Редакционные блоки.** Добавить типы для одиночного изображения, Image + Text, горизонтальной карусели, вертикальной галереи и асимметричной сетки. Массив ссылок задаёт порядок фото, пресет задаёт раскладку. Карусели нужны клавиатурные кнопки, доступные подписи и управление жестами. На узком экране высокая сетка может переходить в вертикальный ряд с тем же порядком. Строгие и экспериментальные пресеты собираются из одних типов блоков со стилями внутри витрины.
5. **Мобильная производительность и выпуск.** Подготовить производные размеры и `srcset/sizes`, резервировать соотношение сторон до загрузки и грузить блоки за первым экраном лениво. Повышать приоритет только первой видимой обложки. Ограничить число фото и вес превью, проверить LCP и CLS на узком экране и медленном соединении. Сначала выпустить новую схему с чтением V1, затем редактор под флагом, проверить публикацию в QA и постепенно включить для брендов.
