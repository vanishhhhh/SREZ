# Вишлисты и публичные подборки

Локальная реализация от 17.11.2026. Избранное `/favorites` сохранено отдельно. Вишлист — именованная подборка товаров, а не корзина и не резерв. Остаток не списывается.

## Модель и ограничения

Новые аддитивные миграции: `012_shareable_wishlists.sql`, `013_wishlist_share_integrity.sql`. Применённые 001–011 не изменяются. Вторая миграция явно запрещает NULL в реквизитах публичной ссылки: обычный SQL CHECK с NULL мог бы дать UNKNOWN.

`wishlists`: владелец, название, описание, private/public, hash и зашифрованный токен, даты. `wishlist_items`: список, товар, nullable вариант, позиция, дата. Есть FK, уникальность `(wishlist_id, product_id)`, отложенная уникальность позиции и проверка принадлежности варианта товару. При удалении варианта предпочтение сбрасывается в NULL; при удалении товара его элемент удаляется по FK.

- До 20 списков на пользователя, до 200 элементов в списке.
- Название: 1–100 Unicode-символов после trim. Описание: до 2000; управляющие символы запрещены.
- Один товар встречается один раз в списке. Вариант — изменяемое предпочтение; другой размер не создаёт вторую строку этого товара. Повторное добавление: 409.
- Позиции начинаются с 0. Перестановка содержит все актуальные ID элементов ровно по одному.
- Можно сохранить существующий вариант с нулевым остатком. Это пожелание; доступность при покупке проверяется отдельно.

## HTTP API

Таблица показывает пути Go. Браузер использует префикс `/api`, который удаляет локальный proxy. Все методы, кроме чтения shared, требуют access Bearer JWT и действующей серверной сессии. CSRF/Origin для cookie-операций auth сохранены.

| Метод  | Путь                            | Тело                                                               | Успех                                          |
| ------ | ------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------- |
| GET    | `/wishlists`                    | —                                                                  | 200, массив собственных summary                |
| POST   | `/wishlists`                    | `{"title":"Мои хотелки","description":"На осень"}`                 | 201, полный список                             |
| GET    | `/wishlists/:id`                | —                                                                  | 200, полный список владельца                   |
| PATCH  | `/wishlists/:id`                | `{"title":"Новое имя","description":"Описание"}`; поля опциональны | 200, полный список                             |
| DELETE | `/wishlists/:id`                | без тела                                                           | 204                                            |
| POST   | `/wishlists/:id/items`          | `{"product_id":1,"product_variant_id":2}`; вариант опционален/null | 201, полный список                             |
| PATCH  | `/wishlists/:id/items/:item_id` | `{"product_variant_id":2}` или null; поле обязательно              | 200, полный список                             |
| DELETE | `/wishlists/:id/items/:item_id` | без тела                                                           | 200, оставшийся список                         |
| POST   | `/wishlists/:id/items/reorder`  | `{"item_ids":[3,1,2]}`                                             | 200, полный список                             |
| POST   | `/wishlists/:id/share`          | `{}`                                                               | 200, включает доступ либо перевыпускает ссылку |
| DELETE | `/wishlists/:id/share`          | без тела                                                           | 200, приватный список                          |
| GET    | `/wishlists/shared/:token`      | —                                                                  | 200, публичная подборка без JWT                |

Тексты передаются строками, не null. Неизвестные JSON-поля, подмена `owner_user_id`, неверные ID и типы отклоняются. Путь принимает канонический положительный десятичный ID. Общий лимит тела — 64 KiB.

Summary: `id`, `title`, `description`, `visibility`, `item_count`, `created_at`, `updated_at`. Полный ответ добавляет `share_path` (null либо `/w/<token>`) и `items`.

Элемент: `id`, `product_id`, `product_variant_id`, `position`, `product`, `variant`. `product` повторно использует DTO карточки каталога, включая цену в копейках, обложку, бренд, цвета/размеры/наличие. `variant`: `id`, `color`, `size`, `stock`, либо null. У владельца скрытый товар остаётся строкой с `product:null`; интерфейс предлагает удалить его. Публичный ответ полностью исключает такую строку и уплотняет позиции.

Публичный DTO имеет только `title`, `description`, `updated_at`, `items`. В нём нет email, owner_user_id, приватного профиля, hash/sealed token, share_path или количества скрытых товаров. Нет публичных мутаций.

| Код | Значение                                                                               |
| --- | -------------------------------------------------------------------------------------- |
| 400 | неверные поля, ID, вариант другого товара, некорректная перестановка                   |
| 401 | нет/истёк JWT или сессия                                                               |
| 404 | чужой/несуществующий список или элемент; недоступный товар; неверная/отозванная ссылка |
| 409 | лимит, дубликат товара, состав списка изменился перед перестановкой                    |
| 500 | операция хранилища не завершилась; приватные детали не выдаются                        |
| 503 | сервис вишлистов не подключён                                                          |

## Согласованность и защита

Обработчик → usecase → сущности/интерфейс репозитория → SQL storage. SQL отсутствует в handler. Владелец берётся из проверенной сессии, не из JSON. Все приватные запросы фильтруются одновременно по id и owner. Для чужого объекта возвращается 404.

Создание блокирует строку пользователя для атомарного лимита 20. Изменения блокируют строку вишлиста `FOR UPDATE`; добавление проверяет публичность и принадлежность варианта. Reorder — транзакция с полным набором ID и deferred constraint, без частично сохранённого порядка. Удаление уплотняет позиции.

Чтение использует read-only REPEATABLE READ и ограниченное количество пакетных запросов с существующим загрузчиком карточек: N+1 нет. Выдаются только опубликованные товары активных брендов. Приватность товара проверяется при каждом чтении, а не только при добавлении. Изменение статуса становится видно при следующем запросе; открытая публичная страница перечитывает данные при focus и раз в 30 секунд.

## Ссылки и ключ

Токен — 32 криптографически случайных байта (256 бит), canonical base64url без padding, 43 символа. Для поиска хранится SHA-256. Для восстановления ссылки владельцем после reload сохраняется AES-GCM ciphertext; plaintext в БД отсутствует. Отдельный стабильный `SREZ_WISHLIST_KEY` — base64, минимум 32 байта, независимый от JWT/CSRF. Внутренний ключ выводится с разделением назначения.

Ключ нужно сохранять вместе с резервной копией `.env` и БД. Его произвольная смена не является процедурой ротации: прежний ciphertext станет нечитаемым владельцу. Для отзыва ссылки используйте API. POST share каждый раз создаёт новый токен и немедленно аннулирует предыдущий; DELETE share очищает оба значения и переводит список в private. Старый адрес получает 404 при следующем запросе. Уже прочитанные посетителем сведения отозвать из памяти или снимков экрана невозможно.

Ответы — `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. HTML также задаёт referrer policy. Go-логгер не пишет URL; proxy frontend пишет только статус, объём и время, без URL/cookie/token. Vite диагностические URL редактирует. Тестовый runner редактирует capability URLs и JWT в текстовых отчётах; traces/video отключены. Скриншоты остаются локальными.

Ссылка — доступ для любого, кто её получил. Не размещайте в названии/описании чувствительные данные. Локальный адрес `http://localhost:5174/w/...` доступен только на этом компьютере. Проверка гостя выполнялась в отдельном browser context; публикация в интернет не выполнялась.

## Frontend

`/wishlists`, `/wishlists/new`, `/wishlists/:id` защищены входом; `/w/:token` доступен гостю. Bookmark на карточке и странице товара открывает общий picker: существующий список или создание нового. Сердце остаётся отдельным избранным. Вариант выбирается из реальной карточки, ручной ввод чужих ID отсутствует.

Есть редактирование, удаление, порядок стрелками, смена варианта, копирование/отзыв/перевыпуск ссылки с подтверждением, защита несохранённой формы, empty/loading/error состояния. Общие transport, session, карточки, изображения, уведомления и дизайн переиспользованы.

## Проверка

PostgreSQL/HTTP-тесты проверяют полный цикл, IDOR/BOLA, mass assignment, скрытые товары, ротацию/отзыв, ограничения и конкурентные изменения, FK и целостность NULL. Browser-тесты выполняют действия owner/guest на реальном Go API. Команды и итоговые результаты — в [отчёте MVP](../frontend/docs/MVP_REPORT.md).
