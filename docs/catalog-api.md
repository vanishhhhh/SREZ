# Публичный список товаров

`GET /products` предназначен для каталога, в том числе карточек React. Авторизация не требуется. В выборку попадают только опубликованные товары активных брендов. Фильтры не меняют данные, статусы и остатки.

## Параметры

| Параметр | Правило |
| --- | --- |
| `category` | `tshirt`, `hoodie`, `pants`, `outerwear`, `footwear`, `accessories`, `other` |
| `brand_id` | Положительный int64. Неизвестный ID даёт пустую выборку |
| `min_price` | Минимальная цена в копейках, целый int64 >=0, включительно |
| `max_price` | Максимальная цена в копейках, целый int64 >=0, включительно; не меньше min_price |
| `size` | Непустой размер до 20 Unicode-символов после trim; регистр не важен |
| `color` | Непустое имя цвета после trim; регистр не важен |
| `sort` | `id_asc`, `price_asc`, `price_desc`, `newest`, `oldest` |
| `page` | Положительный int64, по умолчанию 1; переполнение смещения запрещено |
| `limit` | От 1 до 100, по умолчанию 20 |

Параметры необязательны и объединяются через AND. Size и color требуют stock > 0 у подходящего варианта. При совместном указании размер должен быть доступен именно у указанного цвета. Варианты и изображения не размножают карточки и не влияют на количество товаров в странице.

Известный параметр должен иметь ровно одно непустое значение. Неверный JSON здесь не используется: параметры берутся только из URL. Неверные значения, повторённые известные параметры, некорректное URL-кодирование и переполнение чисел дают `400` с ответом `{"error":"некорректные параметры каталога"}`. Неизвестные параметры игнорируются, как и в прежней ручке.

По умолчанию порядок — ID по возрастанию. `price_asc` / `price_desc` сортируют по цене, затем по ID по возрастанию. `newest` — created_at и ID по убыванию; `oldest` — по возрастанию. Это обеспечивает однозначный порядок даже при одинаковой цене или дате.

Пример:

```sh
curl -i 'http://127.0.0.1:8080/products?category=hoodie&brand_id=2&min_price=200000&max_price=800000&size=M&sort=price_asc&page=1&limit=20'
```

ID бренда берите из GET /brands: PostgreSQL назначает его при создании данных.

## Ответ

Статус `200`, тело — JSON-массив. Прежние поля сохранены; обёртка `{items, meta}` не вводится. Пустая выборка и страница за концом списка возвращают `[]`.

| Заголовок | Значение |
| --- | --- |
| `X-Total-Count` | Число всех товаров после фильтрации, до пагинации |
| `X-Page` | Запрошенная страница |
| `X-Limit` | Размер страницы |
| `X-Total-Pages` | Число страниц; 0 при пустой выборке |

Пример карточки:

```json
[
  {
    "id": 1,
    "brand_id": 1,
    "name": "Футболка База",
    "description": "Хлопковая футболка свободного кроя.",
    "price_kopecks": 250000,
    "category": "tshirt",
    "materials": ["хлопок"],
    "status": "published",
    "created_at": "2026-10-28T12:00:00Z",
    "updated_at": "2026-10-28T12:00:00Z",
    "preview_image_url": "https://example.com/products/1/black.png",
    "brand_name": "Срез Студия",
    "brand_slug": "srez-studio",
    "is_available": true,
    "available_colors": ["Чёрный", "Белый"],
    "available_sizes": ["M", "One Size"],
    "colors": [
      {
        "id": 1,
        "color": "Чёрный",
        "preview_image_url": "https://example.com/products/1/black.png",
        "is_available": true,
        "available_sizes": ["M"]
      },
      {
        "id": 2,
        "color": "Белый",
        "preview_image_url": "https://example.com/products/1/white.png",
        "is_available": true,
        "available_sizes": ["One Size"]
      }
    ]
  }
]
```

Ссылки и ID в примере демонстрационные. Обложка цвета — изображение с минимальной position; обложка товара — первое существующее изображение в порядке ID цвета. Если изображения нет, возвращается пустая строка. Все массивы присутствуют, в том числе пустые `[]`.

`is_available` означает, что сейчас есть хотя бы один вариант со stock > 0. Опубликованный товар с нулевыми остатками остаётся в каталоге: is_available=false, available_colors=[] и available_sizes=[]. Его цвета сохраняются в colors, но недоступные цвета имеют is_available=false и пустой available_sizes.

Общий available_sizes — объединение размеров всех доступных цветов. Для сочетания размера и цвета используйте available_sizes внутри конкретного colors-элемента: общий список не означает наличие каждого размера у каждого цвета. Глобальные и вложенные списки сохраняют порядок цветов/вариантов по ID, дубликаты размеров убираются без учёта регистра. Фильтры выбирают товары, но не обрезают сведения об остальных цветах прошедшего фильтр товара.

## Совместимость и загрузка

Публичный контракт GET /products/:id сохранён. POST /products сохраняет JSON-поля, но теперь требует Bearer JWT и актуальный active owner/editor целевого бренда; создаётся только draft. Dev bypass отсутствует. Публичные GET /brands и /brands/:slug сохранены. Legacy /users отключены; GET/PATCH /profile работают с собственным пользователем по Bearer JWT. /projects остаётся учебным публичным примером. GET /products расширяет элементы массива новыми полями; по умолчанию теперь выдаётся первая страница из 20 элементов. Старые ListPublic и Products.List сохранены для внутренних вызовов.

Для страницы выполняется максимум три SQL-запроса в одном согласованном снимке: count, товары с брендами и пакетная загрузка цветов/вариантов с обложками. Для пустой страницы выполняются первые два. Отдельных запросов на карточку нет. Сам Catalog API не требует отдельной миграции; интегрированные Authentication/RBAC добавляют 003_auth.sql и 004_brand_memberships.sql. Миграции 001/002 сохранены, существующие данные не пересоздаются.
