## Auth

В одном Chromium-контексте вход на `localhost:5174` возвращал 200, а его `GET /api/auth/csrf` тоже возвращал 200. После успешного входа на `localhost:5175` тот же запрос к 5174 возвращал 401. Серверы хранят refresh-сессии в разных базах, хотя оба выставляли HttpOnly cookie с одинаковым именем и путём на одном хосте. Браузер учитывает порт при проверке Origin, а cookie не разделяет по портам.

QA теперь использует отдельное локальное имя cookie. Основной стенд продолжает читать своё прежнее имя. Строгая проверка Origin, CSRF, SameSite, HttpOnly, JWT claims и production-cookie сохранены. Повтор опыта с тем же браузерным контекстом дал 200 на обоих стендах и после повторного перехода на 5174. Уже перезаписанная до исправления локальная сессия требует обычного повторного входа.

На живом QA проверены регистрация, подтверждение через Mailpit, вход по имени и email, неверный пароль, вход до подтверждения, восстановление пароля, защищённые маршруты, обновление cookie и access token, восстановление сессии, logout и одновременная работа вкладок. Live Go проверяет блокирование запросов с чужим Origin и без CSRF. Отказ API проверен браузерной имитацией сетевой ошибки. Истечение подписанного access JWT и последствия повтора refresh проверены Go-тестами. Реальный владелец QA-брендов вошёл и открыл Studio.

## Phase 1 Fixes

Media API различает формат файла, повреждение изображения и превышение разрешения. UploadField уточняет, что пользователь загружал, и сообщает про права, размер, недоступность сервера или занятость обработчика. Проверки исходного MIME, сигнатуры, декодирования, 5 МБ, 8192 px по стороне и 12 млн пикселей сохранены. В браузере проверен повреждённый аватар и последующая успешная загрузка. Те же правила работают для логотипа, баннера, фото товаров и редакционных фото.

Из sidebar Studio убраны ссылки, уже доступные в разделе бренда. В header нулевые счётчики не рисуются. У мобильного предпросмотра есть обозначение открытого состояния, настройки раскрываются только у активного редакционного блока. Сохранение и публикация показывают разные состояния. Кнопки порядка и навигации по галерее проверены с клавиатуры.

## Phase 2 Architecture

Миграция `017_brand_editorial_media.sql` расширяет разрешённые назначения Media Storage и добавляет библиотеку бренда и ссылки снимков. Миграции 001–016 сохранены. V1 читается в прежнем виде. V2 опирается на стабильный ID и положение в массиве. Hero, Story, Products и Contacts остаются единичными, редакционные типы повторяются. В V2 максимум 20 блоков и 8 фотографий в галерее. HTTP ограничен 128 КиБ, JSONB — 160 КиБ с учётом сериализации PostgreSQL. Дополнительные настройки проходят серверные проверки композиции, размера, текста, диапазона фокуса и числа фотографий.

`brand_editorial_image` проходит действующий upload, нормализацию и подтверждение. Пул готовых изображений ограничен 100 на бренд. Владелец может загрузить фото, выбрать его из библиотеки, заменить или использовать в нескольких местах. Страница не принимает URL, object keys или разметку. Сохранение и публикация проверяют наличие, готовность, тип и владельца каждого asset под блокировкой бренда и строк assets. В транзакции обновляются JSON, ревизия и связи снимков. При ошибке откатываются все три. Доступ к неопубликованному фото доступен только активному владельцу. Публичный доступ появляется только у снимка активного бренда.

GC удерживает фото, пока оно используется хотя бы одним снимком. Готовое фото без ссылок остаётся в библиотеке семь дней с загрузки или последнего удаления связи. После повторной проверки под блокировкой оно переходит в действующую очередь отложенного удаления. Удаление блока из черновика сохраняет публичное фото, пока его использует published. [HTTP-контракты](api-reference.md#редакционное-оформление-v2).

## Frontend

Единый renderer обслуживает опубликованную витрину и предпросмотр. У обложки появились пресеты высоты. Фотоблок поддерживает четыре композиции, пропорции, размеры, выравнивание и подпись. «Фото и текст» поддерживает фото с обеих сторон и вертикальную раскладку, управляемые колонки и выравнивание. Горизонтальная галерея использует нативную прокрутку, touch и клавиатурные кнопки. Вертикальная галерея сохраняет порядок и соотношения сторон. Сетка поддерживает асимметрию, диптих, крупное фото с двумя малыми и широкое фото сверху. На телефоне сетка и «Фото и текст» переходят в один столбец. Координаты фокуса одинаково применяются в preview и публичной витрине, отдельная пара для телефона опциональна.

Обложка грузится приоритетно. Остальные managed изображения входят в очередь приблизившись к viewport на 260 px. Один активный запрос на вкладку и Web Locks координируют вкладки одного origin там, где браузер поддерживает API. Общая подписка дедуплицирует загрузку. После ухода последнего потребителя queued запрос отменяется, активный запрос получает AbortSignal, Blob URL освобождается. Настройки Studio вынесены в отдельный динамический JS chunk.

## Remaining Work

Перед PR нужен совместный просмотр Phase 1 и Phase 2. Последний опубликованный снимок хранится без отдельной истории. Изображения живут в библиотеке между сохранениями, поэтому восстановление старой композиции после истечения срока хранения потребует загрузить отсутствующие файлы. Длинные галереи управляются по одному фото, сортировка перетаскиванием и массовая загрузка остаются возможными улучшениями.

Для Phase 3 предложены производные изображения с `srcset/sizes`, замер LCP/CLS на медленном мобильном соединении, визуальный выбор из большой библиотеки и история опубликованных ревизий. Сейчас используется один нормализованный объект на фотографию, с ленивой доставкой и резервированием пропорций. У браузеров без Web Locks ограничение остаётся на уровне вкладки. Полноразмерное превью позволяет проверить композицию в доступной ширине Studio, а публичные viewport проверяются отдельно.
