# SREZ — аудит frontend и продукта

18 ноября 2026 · базовый коммит `81801a12` · целевой срок MVP 15 января 2027

Проверены React-маршруты, клиентские адаптеры, [документированный HTTP API](api-reference.md), регистрации Go handlers и соответствующие usecases. В браузере использован отдельный `srez-mvp-qa` с PostgreSQL, SeaweedFS и Mailpit. Штатным seed добавлены 5 брендов, 21 товар и managed-фотографии. В каталоге было 23 позиции вместе с базовыми демонстрационными записями. Использован Chromium на macOS ARM64 в размерах 1440×900, 834×1112 и 390×844. Это три viewport одного браузера. Изменения интерфейса в эту ветку не входят.

## UX/UI по результатам просмотра

### Главная, каталог и карточка товара

### Managed images

`useImage` планирует ровно один запрос одновременно на весь JS-контекст. Все смонтированные `Media` ставят запрос до создания `img`, поэтому `loading="lazy"` на `img` не откладывает загрузку Blob. Cache обещаний разделён по публичному доступу и пользователю, совпадающие подписчики используют один Blob. Каждый consumer освобождает object URL при cleanup, а запись cache исчезает после последнего подписчика. Cleanup запрещает установку устаревшего результата, но запрос в очереди и уже начатый fetch продолжаются. После быстрой смены фильтра старая очередь может занять слот перед новой. Ошибка загрузки переводит компонент в placeholder без встроенного повтора. Backend допускает две выдачи одновременно на процесс и отвечает ошибкой при занятом слоте. [useImage.ts:4](../frontend/src/features/media/useImage.ts#L4), [useImage.ts:23](../frontend/src/features/media/useImage.ts#L23), [ui.tsx:261](../frontend/src/components/ui.tsx#L261), [ui.tsx:301](../frontend/src/components/ui.tsx#L301), [media.go:49](../internal/handler/media.go#L49), [media.go:491](../internal/usecase/media.go#L491)
